# 0013 Canon UFR II 6.40-1.10

Updates the driver version in [0003](0003-printing-driver.md); everything else there stands.

**Decision:** pin Canon's `linux-UFRII-drv-v640-m17n-10.tar.gz` (6.40-1.10, Canon page updated
2026-10-21), SHA-256 `d688958358ab9d5f86fa66a5477399c448ebb6941820cdfd7368cbb6170337c2`. The user's
choice (2026-11-23), after the paper test with 1.05 passed (test page and a 2-page duplex job).

**Read before pinning (2026-11-23, laptop):** same archive layout, the role's `.deb` path
`ARM64/Debian/cnrdrvcups-ufr2-uk_6.40-1.10_arm64.deb` exists. Same dependencies. `postinst`/`postrm`
only symlink PPDs and restart CUPS. Same security-relevant parts as the 1.05 on the board: setuid root
`/usr/bin/cnpkmoduleufr2r`, world-writable `/etc/cngplp2/{account,options}`. `CNRCUPSMF4350ZK.ppd`
is byte-identical to 1.05 (MD5 `1c9a330f…`). The README lists no change for the MF4320d.

**Rollback to 1.05:** set these in `ansible/group_vars/print_server.yml`

```yaml
printing_canon_version: "6.40-1.05"
printing_canon_url: https://gdlp01.c-wss.com/gds/8/0100007658/51/linux-UFRII-drv-v640-m17n-05.tar.gz
printing_canon_sha256: ff69c541b9e12df716fa649cb5307839bb2a4d9ba05dd93b81435df1f60c7834
```

and run `sudo apt remove cnrdrvcups-ufr2-uk` once first, as APT won't downgrade by itself.
