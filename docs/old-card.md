### Security problems (fixed on the new card by [0005](decisions/0005-exposure.md))

| | Finding | Action |
|---|---|---|
| High | SSH accepts passwords; two sudo users (`radxa`, `rock`) come from the public image. Passwords were not tested | change both or lock `rock`, then key-only SSH |
| High | CUPS has `_remote_admin=1` and `_remote_any=1`: admin pages and access from any address | limit to the local subnet, no remote admin |
| Medium | scanservjs answers on 8080 without login and can show earlier scans | restrict to the LAN, never port-forward |
| Medium | scanbm on 6566, all interfaces | remove scanbd/inetd if unused |
| Medium | `cups-browsed` runs. It had remote code execution bugs in 2024 and is only needed to discover other printers | disable |
| Medium | No updates applied since about July; Radxa test channels | update, switch to release channels |
| Low | No active ufw, firewalld or nftables service | fine on a trusted LAN |

The board had no global IPv6 address, so exposure is LAN-only unless the router forwards ports.

### Defects

- `rsdk-t4` hangs on `reboot` ([reported](https://github.com/radxa-build/radxa-a733/issues/34), fixed in t5): use poweroff and a power cycle on the old card
- `lightdm` fails at every boot (203/EXEC) and `plymouth-quit` fails: desktop leftovers on a headless box
- `/usr/lib/environment.d/99-environment.conf` links to `/etc/environment`, whose `export` line systemd rejects
